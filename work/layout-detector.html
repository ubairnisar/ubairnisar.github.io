Case files / Siparadigm Diagnostic

A layout detector built on an OCR model's eyes

A vision-language model could already draw accurate layout boxes, but it wrote them out one token at a time: slow, and sometimes inventing boxes that weren't there. The question was whether we could keep what the model sees, drop the slow text generation, and get the same understanding in a single fast pass.

The idea

Keep the eyes, replace the mouth.

What worked

A VLM reads layout well

An OCR-tuned vision-language model placed layout boxes accurately because its vision encoder had learned what documents look like.

The bet

Attach a detector to its vision tower

Reuse the model's vision encoder as the backbone and put a real detection head on top: every box predicted at once, each with a confidence score, nothing generated token by token.

What it fixes

Speed and invented boxes

One forward pass per page instead of long text generation, and a detector can't hallucinate coordinates for something it never scored.

How it got here

Seven iterations, each driven by a failure.

The model wasn't designed in one go. Each version fixed the weakest point the previous one exposed, and every change had to show up in the numbers or in real pages.

01
Starting point

A query-based head on frozen features

The first draft bolted a DETR-style decoder onto the frozen vision tower. A critical review before any long training run found it would never converge into a usable detector: no confidence score per box, boxes that could come out inverted, and no positional information for the decoder.

Decision: stop and rethink before spending GPU days on a design that couldn't work.
02
Proof that the idea works

A dense head on the 2D feature grid

A CenterNet-style head that predicts a confidence heatmap and box edges per grid cell, trained on features cached once from the tower. It learned quickly, which confirmed the tower's features carry real layout information.

AP50 0.28 → 0.59 in 4 epochs~1 min per epoch on cached features
Then: swapped in an OCR-tuned VLM's tower, loading only the vision weights instead of the whole 5B-parameter model.
03
Scaling up

From 8k pages to a 74k-page, 4-class dataset

The cache that made iteration fast would have needed about 390 GB for 74k pages. Features moved to on-the-fly computation with random subsets each epoch, and the head became multi-class with per-class confidence and class-aware evaluation.

Engineering: the cost math came first. Caching, sampling and micro-batching were chosen from measured throughput, not guessed.
04
v1 · production-grade training

Plugged into a mature detector training stack

Rather than re-implement training, the custom backbone was wired into Ultralytics' trainer to reuse its loss, augmentation, EMA and mAP evaluation.

mAP50 0.853mAP50-95 0.688marginalia AP50 0.781,500 validation pages · 15.5k boxes
Diagnosis: a high mAP50 with a much lower mAP50-95 means the right regions are found but the edges are loose, because the tower's final map sees the page in 32-pixel cells.
05
v2 → v3 · research-driven redesign

Finer features, a fine-tuned tower, a better head

Ideas from current state-of-the-art detectors and document models: features from four depths of the tower, a pixel CNN for detail at stride 8, a multi-receptive block for the huge range of element sizes, and a top-down plus bottom-up neck. Then the last tower blocks were unfrozen and the head switched to an end-to-end design.

epoch 2 already at 0.856 / 0.691= v1's fully trained result
Found along the way: the training framework silently re-enabled gradients on "frozen" weights, which would have trained the whole tower. Frozen weights were moved out of its reach.
06
The semantics gap

Why it still acted like a pattern detector

On a 1983 typewriter financial report, a borderless table came out as six fragments. The vision tower is the model's eyes, but the interpretation in a VLM happens in its language layers. And mosaic augmentation, which stitches four pages together, was erasing exactly the page-level cues that layout depends on.

Response: structure-aware post-processing that rejoins fragments whose column gutters line up and keeps a complete table over its pieces, plus per-class thresholds and multi-scale box fusion tuned on held-out pages.
07
Now

A set-level decoder, and a controlled study

A query-based decoder that reasons about all boxes together was trained head-to-head with the dense head, since a set-level loss penalises cutting one table into many. It reached similar accuracy, and the investigation showed that "NMS-free" in principle is not the same as duplicate-free in practice.

query decoder: epoch 1 → 2 +10.9 mAP50-95similar to the dense head by epoch 12
Next: a controlled study on a public benchmark: do OCR-tuned VLM vision towers make better layout backbones than generic ones, and do the language layers add semantics the tower lacks?
One failure, up close

When one table looks like six.

A borderless table with only whitespace between sections. A local detector sees six blocks; a person sees one table, because the columns line up. Schematic, not the real page.

What I learned

The thinking behind the model.

01

The eyes aren't the brain

A VLM's vision tower encodes what each region looks like; reading and relating happen later, in its language layers. Borrowing the tower gives perception, not understanding.

02

Read the gap between metrics

mAP50 high, mAP50-95 low pointed straight at loose edges and coarse features, which told me where to add resolution instead of guessing.

03

Augmentation can erase meaning

Mosaic is great for photos but stitches four pages into one, destroying the headers, columns and margins that define a document's layout.

04

Scores aren't comparable across sizes

A complete table scored lower than its own sections, and a filter that summed fragment scores always preferred splitting. Decisions on structure beat decisions on raw scores.

05

"NMS-free" isn't duplicate-free

End-to-end heads learn not to need NMS, but at low thresholds the same box can still appear once per class. Measure duplicates directly; don't trust the label.

06

Do the cost math first

A 390 GB cache, 2-hour epochs and a crashing machine all had the same fix: measure throughput and memory, then choose caching, sampling and batch sizes from the numbers.

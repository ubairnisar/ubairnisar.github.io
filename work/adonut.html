ADONUT: agentic document understanding

A production pipeline that turns complex documents, with tables spanning pages, deep section hierarchies, marginalia and figures, into one clean, schema-valid JSON tree that downstream systems can trust.

Problem

Standard extractors read documents page by page. Tables that continue across pages get split, section nesting is lost, and LLM-proposed boxes drift from the real text, so downstream data is wrong.

Approach

Separate where things are (layout + exact OCR geometry) from what they mean (type-specific extraction), link regions across pages, rebuild the section tree, then extract every region in parallel with the cheapest method that is good enough.

Result

State-of-the-art table recognition and hierarchy scores, a near-perfect layout stage, and a single structured document per file, delivered over RabbitMQ with a Pydantic schema.

Engineering decisions

The choices that made it work.

01

Models say where, OCR says exactly where

LLM and VLM boxes are approximate; OCR word positions are exact. Box refinement snaps every proposed region to real word geometry, so crops and grounding text line up.

02

Fix the page break problem first

Cross-page linking happens before extraction, so a table or section that continues on the next page is treated as one object, and multi-page tables are merged in a single call.

03

Pay for intelligence only where needed

Prose reuses OCR at zero model cost, simple tables get a lite model, complex ones a stronger model, and every region runs in parallel. Accuracy goes up while cost per page goes down.

04

A custom detector when off-the-shelf stalled

Qwen-VL backbone with residual connections, multi-scale feature fusion and dilated convolutions, paired with an RT-DETR head: mAP 0.67 → 0.84 and a 99.4% F1 layout stage.

05

Structure is a first-class output

Regions become a section tree before extraction and go back into the same tree afterwards, preserving nesting and reading order, which is what HRDoc STEDS measures.

06

Fast, cheap, self-hosted serving

Models run on vLLM with TurboQuant quantisation and speculative decoding; jobs flow over RabbitMQ and leave as schema-validated Pydantic JSON.

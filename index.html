General skills first

How I solve problems, before any model is picked.

Tools change every few months. The way I work does not: understand the problem, build the simplest thing that can work, measure it honestly, make it fast and cheap, and own it in production.

01

Understand the real problem

Work with the people who will use it, then define what "good" means before writing any model code.

Upwork clients worldwide, from requirements to delivery
02

Start simple, go custom when needed

Fine-tune what exists first; design a new architecture only when the numbers say it is needed.

Custom layout detector: mAP 0.67 → 0.84
03

Measure honestly

Public benchmarks, held-out data and human-in-the-loop checks, so progress is real and not a demo.

Benchmarked on OmniDocBench, HRDoc, RealDocBench
04

Make it fast and cheap

Quantization, speculative decoding and efficient serving, so the system is affordable at real traffic.

vLLM + TurboQuant + speculative decoding
05

Ship it and own it

Deploy, monitor, label what fails and retrain. A model only counts once people rely on it.

Live at Al Meera, Qatar: ~2,000 shoppers/day
